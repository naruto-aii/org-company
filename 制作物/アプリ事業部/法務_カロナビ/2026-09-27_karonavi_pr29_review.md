## 2. app-privacy-draft.md の照合

**前回判定との一致：一致。** Product Interaction（Analytics）、Purchase History（Analytics）、User ID（App Functionality＋Analytics）、いずれもユーザに関連付けあり、トラッキングなし、Product Personalization なし。

**申告漏れ・要検討（Appleの区分による）**

1. **Health & Fitness > Fitness が漏れています（要追加）。** Appleの定義は「Fitness and exercise data」です。アクティブエネルギー（`health_snapshots` でサーバー保存）と運動記録（`exercise_entries`）はこれに当たると読めます。目的は App Functionality、関連付けあり、トラッキングなしです。なお、ワークアウトは端末内の Isar にだけ保存するので「収集」には当たりません（"Data that is processed only on device is not collected"）。
2. **食事・アルコール・体重の手入力の記録。** 回答案はこれらを Other User Content としています。Appleは、特定の種類のデータを入力させる場合は、その種類として申告するよう求めています（"if you ask a user to input a specific data type ... you'll need to disclose the specific type of data"）。Healthの定義には「any other user provided health or medical data」も含まれます。体重は Health に入っているので可です。食事・アルコールの記録も Health に含めるのが保守的です（判断事項）。
3. **公開食品への評価（Good/Bad）・通報・ブロック**が回答案の根拠一覧にありません。サーバーに保存しているのであれば、Other User Content（または Product Interaction）の根拠として追記してください。
4. **Sign in with Apple のリフレッシュトークン（このPRで新たに保存）。** 回答案は「運営が分類を確認」としています。Appleは、保存しないトークンは申告不要としています（"if an authentication token ... is sent on a server call and not retained ... you do not need to disclose"）。今回は保存するので、Other Data Types（App Functionality）として申告するのが保守的です。申告不要と判断する場合は、その理由を記録しておいてください（判断事項）。
5. **PrivacyInfo.xcprivacy と回答案の食い違い。** マニフェストに Purchase History・Other User Content（と Fitness）が入っていません。回答案とマニフェストを揃えてください。
6. 申告不要と読めるもの：メールでの問い合わせはアプリ外で送るため、アプリによる収集には当たらないと読めます（未確認）。氏名は保存しないので Name は不要です。ただし、SIWAで fullName を要求しながら保存しないのであれば、要求そのものをやめることも検討してください（データ最小化）。Payment Info は不要です。
7. **privacy.html との食い違い：** 大きなものはありません。ただし、リフレッシュトークンは回答案だけにあり、ポリシーにはありません。

## 4. 根拠（要旨）

- 個人情報保護法 17条1項・2項、18条、21条1項・3項、22条、23条、27条5項1号、28条、32条1項（施行令10条1号）、33条5項
