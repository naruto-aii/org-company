# 役割スキル

Cursor が読む場所は、このフォルダ（`.cursor/skills/<役割>/SKILL.md`）である。トップレベルの `skills/` には置かない。

正は各人のプロフィールと [運用ルール.md](../../運用ルール.md) である。スキルとプロフィールが食い違ったら、プロフィールと運用ルールに従い、スキルを直す。役割は34名。社長は含まない。秘書はいない。新しい役割は作らない。

## どう呼ぶか

1. 依頼は [VP](VP/SKILL.md) に渡す。VPが担当の SKILL.md を選び、作った人と別の役割に確かめさせ、まとめて返す。
2. VPは自分から動かない。依頼を渡されたときだけ動く。
3. 役割がすでに決まっている指示は、下の表のフォルダの `SKILL.md` を読んで従う。フォルダ名はプロフィールの名前と同じ。
4. Slack、カレンダー、Gmail、フォーム受付の自動起動は、VPスキルの外である。今の社長補佐が担う。

社長への直接連絡はVP以外禁止。報告はVPへ届く。役員（COO、CSO、CPO、CTO、CFO、CMO、CCO、CRO）がVPへ返す。GMとその部下は上司に渡し、役員がVPへ届ける。GMと部下からVPへは直接送らない。

## 議事録

Slack の #議事録 では、親投稿は罫線（━ を10個）で挟んだ3行だけにする。

```
━━━━━━━━━━
日付：M/D
議題：（議題）
参加者：（グループ名と名前）
━━━━━━━━━━
```

日付は月/日（例: 日付：9/27）。決まったこと、社長の判断が要ること、次にやること（担当と期限）はスレッドに書く。全文のファイルは `議事録/<グループ名>/YYYY-MM-DD_議題.md`。経営会議の議事録はVPが書く。ほかは、そのグループの最上位が書く。

## 制作物

事業部ごとの場所は `制作物/<事業部>/<項目>/` である。既存の項目フォルダがある成果はそこへ足す。フォルダが無いときだけ、各スキルに書いた項目名で作る。作った人は `/workspace/制作物-queue/` の同じ相対パスに置く。`制作物/README.md` の「VPにパスを1行」は、役員がVPへ渡す段である。役員以外は上司に1行で渡し、役員がVPへ渡す。VPが `制作物/` へ反映する。`作業ファイル/` は成果物の置き場所にしない。
